# 可替换的低成本数字孪生工作流

## 设计目标

本项目定义工作流和节点之间的开放数据契约，而不是绑定某个 AI、3D 软件、Web 引擎或设备平台。Codex、Blender、Three.js 和模拟 WebSocket 服务只是 v0.1 的一组参考实现。

三项基本原则：

1. **模型无关：** ChatGPT、Codex、Gemini、Claude、本地模型、规则程序或人工编辑器都可以产生符合协议的空间语义与体验配置。
2. **3D 执行器无关：** Blender 可以被 Three.js 直接生成器、Unity、Unreal、Godot、Omniverse 或其他 CAD/BIM 工具替换。
3. **数据源无关：** 运行时通过适配器接入 MQTT、Prometheus、Zabbix、OPC UA、DCIM、CMDB 或其他已授权系统。

## 建议工作流

```text
多角度图片 / 平面图 / 已知尺寸 / 设备清单
                        ↓
       可替换的空间理解 AI 或人工录入
                        ↓
       带证据、不确定性和尺度的场景语义
                        ↓
            可替换的 3D 场景执行器
                        ↓
       Web 校准：选择对象、调整位置与尺寸
                        ↓
          选择现实设备并确认资产绑定
                        ↓
       勾选指标、单位、数据点位与告警状态
                        ↓
        生成声明式动态参数与行为配置 JSON
                        ↓
      用户用自然语言描述页面和三维动态效果
                        ↓
          可替换的体验配置 AI 或编辑器
                        ↓
        可替换 Web/3D 运行时呈现动态孪生
```

这是“双阶段 AI”结构：

- **空间理解节点**把现实资料变成可检查的空间初稿；
- **体验配置节点**把自然语言变成可检查的指标、状态、交互和视觉规则。

两个节点可以使用同一模型，也可以分别使用不同模型或完全由人工替代。AI 输出必须先成为声明式数据，不应把不可追踪的代码修改作为唯一结果。

## 开放数据边界

建议逐步将数据拆分为以下文件或等价 API：

| 数据 | 职责 |
| --- | --- |
| `evidence.json` | 图片、视角、来源、尺度依据和采集时间 |
| `scene.json` | 房间、对象、组件、空间关系、位置和尺寸 |
| `assets.json` | 现实设备的稳定身份与业务属性 |
| `bindings.json` | 三维对象与现实设备的人工确认映射 |
| `metrics.json` | 数据源、点位、单位、刷新周期和新鲜度要求 |
| `behaviors.json` | 状态判断、颜色、轮廓、闪烁、动画和恢复规则 |
| `experience.json` | 面板、筛选、点击、导航和页面布局 |
| `changes.json` | AI 建议、人工修改、确认人、时间和版本差异 |

v0.1 暂时把其中部分字段放在场景对象 metadata 和 Web 演示代码中。后续迭代应逐步拆分，而不是立即设计一个庞大且未经验证的统一标准。

## 动态配置示例

下面仅展示目标形态，不代表 v0.1 已经实现该完整 Schema：

```json
{
  "binding": {
    "object_id": "rack_b3",
    "asset_id": "RACK-B3"
  },
  "metrics": [
    {
      "id": "temperature",
      "source": "prometheus-main",
      "point": "rack_temperature_celsius{rack=\"B3\"}",
      "unit": "°C",
      "display": "detail_panel"
    }
  ],
  "states": [
    {
      "when": "temperature >= 40",
      "level": "alarm",
      "effects": [
        { "type": "color", "value": "#ff304f" },
        { "type": "pulse", "speed": 1.5 },
        { "type": "outline", "value": "#ff8090" }
      ]
    }
  ],
  "stale": {
    "after_seconds": 30,
    "state": "unknown",
    "color": "#718096"
  }
}
```

用户可以继续描述：“温度超过 40°C 时机柜变红并闪烁；数据中断后变灰；点击后显示最近 30 分钟曲线。”体验配置节点把描述转换为待确认配置，运行时解释配置，不要求重新生成整套页面。

## 人工确认与安全边界

- 缺少尺度依据时，AI 只能标记估算，不能把推断写成测量值。
- 资产绑定必须保留建议、确认和解除记录，不能只依赖名称相似度。
- 生产告警阈值、单位和恢复条件必须由有权限的人确认。
- 数据断连和过期必须进入 `stale` 或 `unknown`，不能继续显示为正常。
- 首阶段只读展示，不允许 AI 或孪生页面直接控制现实设备。
- 更换模型、3D 执行器或运行时，不应覆盖已经确认的绑定与人工校准。

## 项目的独立价值

通用 AI 可以完成某次场景和页面开发。本项目要验证的独立价值是：第二个现场是否能够复用相同的数据契约、组件、连接器、确认记录和验收方法，而不必再次从一段新对话和一套新代码开始。

如果开放规范增加的使用成本大于它带来的复用和风险降低，就应该删减规范。低成本不仅是开发费用，还包括流程复杂度、纠错成本、失败风险和长期维护投入。
